# ServiceAutoPassport

Приложение WinForms на .NET 8 для заполнения паспорта сервиса в Confluence. Использует страницу из буфера обмена или сохранённый шаблон и помещает заполненную страницу в буфер в формате HTML.

## Подготовка

1. Установите .NET 8 Desktop Runtime или .NET 8 SDK для Windows.
2. Убедитесь, что каталоги YAML и J2 находятся внутри локальных Git репозиториев с `remote origin`: из них строятся ссылки для карточки.
3. Для сохранения шаблона или прямого заполнения скопируйте **полную страницу** в редакторе Confluence. Буфер должен содержать формат `HTML Format`.

## Запуск

Запустите `artifacts/win-x64/ServiceAutoPassport.exe` или выполните на Windows:

```powershell
dotnet run --project src/ServiceAutoPassport
```

В окне выберите корень `app-params` и папку сервиса. Приложение предложит имя сервиса по имени J2-папки и выберет совпадающую YAML-папку, если она есть. Имя можно исправить вручную. Затем выберите основной J2 файл. Для UI доступен пункт «Без J2 (для UI)». Название сервиса и команду можно оставить пустыми: значения сохранятся из шаблона в буфере. Флажок «Приоритет» у каждого поля определяет, заменит ли введённый текст значение шаблона. Если флажок снят, текст поля используется только для пустой ячейки шаблона. Флажки сохраняются отдельно для каждого сервиса.

Кнопка «Описания ключей…» открывает список пар «имя переменной J2 → описание». В новых настройках список пуст. Добавляйте, меняйте и удаляйте пары в этой таблице; кнопка «Сохранить» записывает их в локальные настройки для всех сервисов. Кнопка «Вставить из Excel…» принимает сразу две колонки: ключ и описание, по одной паре в строке. Разделитель — табуляция или первый пробел после ключа; первая строка «Ключ / Описание» необязательна. Уже существующие ключи обновляются. При генерации описание подставляется в первую колонку таблицы настраиваемых параметров или в название микросервиса для ключей `SVC_`. Для ключей без пары остаётся текст из шаблона либо имя переменной.

Поле «Адрес доменного API» позволяет ввести имя переменной вручную или выбрать его из списка. При наборе нескольких символов появляются подсказки по началу имени. Список содержит имена переменных из объединённых YAML app-params по алфавиту, включая переменные, которые не используются в собственном J2 сервиса. Введённое имя записывается в поле карточки «app-params. Переменная содержащая адрес доменного API». Пункт «Из шаблона» или пустой ввод сохраняют исходное значение страницы. Ввод запоминается отдельно для каждого сервиса, даже если имени нет в списке; список обновляется при смене app-params или сервиса и кнопкой «Обновить» рядом с ним.

Описание можно сохранить как HTML-фрагмент: отметьте «HTML» у строки или откройте «Редактор HTML…» для многострочного кода. В редакторе HTML можно вставить код как текст или скопировать фрагмент из Confluence и нажать «Взять HTML из буфера». При массовой вставке HTML-теги распознаются автоматически; режим можно поправить вручную. Обычные описания экранируются как текст, а HTML-фрагменты сохраняют ссылки и атрибуты макросов Confluence в итоговом буфере. Вставка ссылки внутри готовой HTML-таблицы сама по себе не гарантирует превращения в Jira-макрос: [Atlassian описывает автоконвертацию](https://confluence.atlassian.com/display/DOCM/Jira+Issues+Macro) для прямой вставки URL в редактор. Для точного макроса используйте HTML уже созданного в Confluence макроса и проверьте результат вставки в своей версии редактора.

Поля «Название сервиса» и «Команда» тоже принимают HTML-фрагмент. Вставьте код в поле и отметьте «HTML» либо нажмите «Редактор…», вставьте код или возьмите HTML скопированного фрагмента Confluence из буфера. Редактор автоматически включает режим HTML. Фрагмент вставляется целиком в соответствующую ячейку карточки; при выключенном «HTML» содержимое поля остаётся обычным текстом. Флаги HTML и «Приоритет» сохраняются отдельно для каждого сервиса. Макросы и их `data-macro-*` атрибуты сохраняются как HTML; итог работы редактора Confluence зависит от того, как он обрабатывает вставку.

Скопируйте полную исходную страницу Confluence и нажмите «Сохранить буфер как шаблон», чтобы использовать её позднее. Кнопка «Заполнить шаблон из буфера» работает непосредственно с текущей полной страницей в буфере. Кнопка «Сохранённый шаблон + буфер» берёт сохранённую страницу, переносит из текущего буфера найденные значения карточки, комментарии микросервисов и объектов доступа, настройки параметров и дополнительную информацию, затем применяет данные YAML и J2. В этом режиме текущий буфер может содержать только часть страницы. Результат обеих команд копируется в буфер для вставки в Confluence.

В таблицах микросервисов и настраиваемых параметров достаточно строки заголовка: если строки-образца нет, приложение создаёт строки по структуре заголовка. Это позволяет повторно использовать страницу, в которой после предыдущей генерации эти таблицы опустели.

Карточка распознаётся и внутри таблиц макросов Confluence. Из старой страницы переносятся все совпавшие поля шапки, включая описание, поля Vault, адрес доменного API, схемы, согласования, HealthCheck и микрофронты. Поля сопоставляются по основному названию без поясняющих подсказок, завершающих двоеточий и пустых служебных колонок. Вложенные таблицы и макросы в значениях сохраняются целиком. После переноса применяются значения из UI и YAML. Макросы карточки не используются как источник блока «Дополнительная информация».

Поле «Vault. Переменная с ключами для предоставления доступа» заполняется именем единственной переменной из значения `GrpcSettings__ServerSettings__AllowedServices` в выбранном secrets J2. Например, `"{{GRPC_SETTINGS_SERVER_SETTINGS_ALLOWED_SERVICES}}"` даёт `GRPC_SETTINGS_SERVER_SETTINGS_ALLOWED_SERVICES`. Найденная переменная заменяет значение старой страницы; если подходящей записи в secrets нет, значение сохраняется из шаблона.

В «Объектах доступа» остаются только строки, содержащие имена переменных из выбранных `*.deploy.j2` или `*.secrets.j2`. В колонках адреса и Vault из исходного шаблона удаляются имена, которых нет в этих файлах; новые имена по совпадению префикса не добавляются. Несколько имён в одной ячейке проверяются по отдельности, в том числе если они стоят в одном абзаце.

В таблице настраиваемых параметров колонка «Значение по умолчанию» для ключей из общих YAML содержит пометку «Дефолтное значение в базовых параметрах». Для остальных ключей, найденных в YAML сервиса, выводится итоговое значение после объединения слоёв, включая `*-prod`. Значение заменяет текст из шаблона и вставляется как обычный текст. Если ключа в YAML нет, содержимое ячейки сохраняется из шаблона.

Папка сервиса в `app-params` необязательна. Если её нет, используются только значения из корневого `application.yml` или `application.yaml`; `application-prod` не загружается. Ссылка в карточке ведёт на корень `app-params`. Если `deploy_num`/`replicas` отсутствуют или пусты, количество Pod равно `1`. Отсутствующие `namespace`/`namespace_name` сохраняют значение из скопированного шаблона.

Пустые YAML-файлы допускаются: они не добавляют значений, поэтому берутся параметры из других YAML-слоёв. Если ресурс не указан и подходящий дефолт отсутствует, в карточке выводится «значение не найдено».

Requests и Limits вычисляются отдельно для CPU и памяти: `cpu_req`, `mem_req`, `cpu_lim`, `mem_lim` имеют приоритет над `DEFAULT_RESOURCES_{UI|API|DAEMON}_{REQUEST|LIMIT}`. Дефолты читаются как YAML-объекты с ключами `cpu` и `memory` из объединённых слоёв с обычным порядком перекрытия. Значения, взятые из этих объектов, получают пометку «(значение по умолчанию)». Фиксированных резервов ресурсов нет; отсутствие каждого значения отмечается отдельно.

Тип определяется по нормализованному имени деплоя: сначала проверяются правила webapi (включая api, bff, grpc и другие согласованные имена), затем daemon (worker, scheduler, integration и другие). Если ни одно правило не совпало и в папке сервиса и её подпапках нет `appsettings*.j2`, используется UI. Имена файлов проверяются без учёта регистра; служебные каталоги `.git`, `node_modules`, `bin`, `obj` и символические ссылки не просматриваются. Если тип не определён, используются только явно заданные ресурсы.

Для UI основной J2 необязателен. При выборе «Без J2 (для UI)» таблицы микросервисов, объектов доступа и параметров сохраняются из шаблона; имя деплоя и ссылка на репозиторий строятся по выбранной папке. В поле «Шаблон конфига» выводится «Не используется». Для прочих типов основной J2 требуется.

Для памяти в Requests и Limits числовые значения `mem_req` и `mem_lim` дополняются единицей `Mi`; значения с уже указанной единицей, например `800Mi` или `1Gi`, выводятся без изменений.

Индикатор в окне автоматически проверяет HTML в буфере обмена. Он узнаёт шаблон по характерным полям даже в скопированной отдельно карточке сервиса. Это предварительная проверка: прямое заполнение требует полной исходной страницы, а режим с сохранённым шаблоном принимает фрагмент. После генерации индикатор сообщает, что в буфере уже готовый паспорт.

Пути, выбранный сервис, название, команда и шаблон по умолчанию сохраняются в `%LOCALAPPDATA%\ServiceAutoPassport\settings.json`. При первом запуске приложение также прочитает прежний `settings.json` из текущей папки или рядом с исполняемым файлом, если он есть. Рядом с `appsettings.deploy.j2` ищется `appsettings.secrets.j2`; также поддерживается `secrets.j2`. Для числа Pod принимаются `deploy_num` или `replicas`, для пространства имён — `namespace` или `namespace_name`. Если `autoscale` отсутствует или пуст в YAML, в карточке указывается «нет». Файлы `.yaml` также поддерживаются.

Готовый Windows файл находится в `artifacts/win-x64/ServiceAutoPassport.exe`; для него нужен установленный .NET 8 Desktop Runtime. Чтобы пересобрать его:

```powershell
dotnet publish src/ServiceAutoPassport/ServiceAutoPassport.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o artifacts/win-x64
```

При ошибке генерации исходный буфер не меняется. Для прямого заполнения следующего сервиса вновь скопируйте исходную страницу шаблона. Режим с сохранённым шаблоном восстанавливает его исходные строки перед заполнением.

## Проверка

```powershell
dotnet test ServiceAutoPassport.sln -c Release
```

Тесты проверяют слои YAML, обработку встроенного сокращённого шаблона Confluence, сохранение макросов и формирование `HTML Format`. Локальные экспорты буфера для ручной проверки хранятся в `artifacts/one_block` и `artifacts/whole_page` и не входят в Git. Фактическую вставку в Confluence нужно проверить в Windows с доступом к редактору.
