# ServiceAutoPassport

Приложение WinForms на .NET 8 для заполнения паспорта сервиса в Confluence. Использует страницу из буфера обмена или сохранённый шаблон и помещает заполненную страницу в буфер в формате HTML.

## Подготовка

1. Для AIO-сборки установка .NET не требуется. Для обычной сборки установите .NET 8 Desktop Runtime или .NET 8 SDK для Windows.
2. Убедитесь, что каталоги YAML и J2 находятся внутри локальных Git репозиториев с `remote origin`: из них строятся ссылки для карточки.
3. Для сохранения шаблона или прямого заполнения скопируйте **полную страницу** в редакторе Confluence. Буфер должен содержать формат `HTML Format`.

## Запуск

Для распространения используйте `artifacts/win-x64-aio/ServiceAutoPassport.exe`: это один EXE для Windows x64 со встроенным .NET 8 и Windows Desktop Runtime. Достаточно передать этот файл пользователю, отдельная установка .NET не нужна.

Обычная сборка находится в `artifacts/win-x64/ServiceAutoPassport.exe`. Для запуска из исходников выполните на Windows:

```powershell
dotnet run --project src/ServiceAutoPassport
```

В окне выберите корень `app-params` и папку сервиса. В поле «Имя сервиса / YAML-папка» подставится нормализованное имя папки. По этому имени приложение ищет YAML-папку в app-params. Ручная правка действует до смены папки или перезапуска. Пустое поле означает имя папки. Затем выберите основной J2 файл. Для UI доступен пункт «Без J2 (для UI)». Если оставить название сервиса и команду пустыми, значения сохранятся из выбранного шаблона. Флажок «Приоритет» у каждого поля определяет, заменит ли введённый текст значение шаблона. Если флажок снят, текст поля используется только для пустой ячейки шаблона. Флажки сохраняются отдельно для каждой папки сервиса.

Кнопка «Описания ключей…» открывает список пар «имя переменной J2 → описание». В новых настройках список пуст. Добавляйте, меняйте и удаляйте пары в этой таблице; кнопка «Сохранить» записывает их в локальные настройки для всех сервисов. Кнопка «Вставить из Excel…» принимает сразу две колонки: ключ и описание, по одной паре в строке. Разделитель — точка с запятой, табуляция или первый пробел после ключа; первая строка «Ключ / Описание» необязательна. При совпадениях импорт предложит заменить текущие значения или оставить их. Новые строки добавляются в обоих случаях. При генерации описание подставляется в первую колонку таблицы настраиваемых параметров или в название микросервиса для ключей `SVC_`. Для ключей без пары остаётся текст из шаблона либо имя переменной.

Поле «Адрес доменного API» позволяет ввести имя переменной вручную или выбрать его из списка. При наборе нескольких символов появляются подсказки по началу имени. Список содержит имена переменных из объединённых YAML app-params по алфавиту, включая переменные, которые не используются в собственном J2 сервиса. Введённое имя записывается в поле карточки «app-params. Переменная содержащая адрес доменного API». Пункт «Из шаблона» или пустой ввод сохраняют исходное значение страницы. Ввод запоминается отдельно для каждого сервиса, даже если имени нет в списке; список обновляется при смене app-params или сервиса и кнопкой «Обновить» рядом с ним.

Описание можно сохранить как HTML-фрагмент: отметьте «HTML» у строки или откройте «Редактор HTML…» для многострочного кода. В редакторе HTML можно вставить код как текст или скопировать фрагмент из Confluence и нажать «Взять HTML из буфера». При вставке обычных пар из Excel HTML-теги распознаются автоматически. Экспорт сохраняет состояние флажка «HTML» каждой строки. Обычные описания экранируются как текст, а HTML-фрагменты сохраняют ссылки и атрибуты макросов Confluence в итоговом буфере. Вставка ссылки внутри готовой HTML-таблицы сама по себе не гарантирует превращения в Jira-макрос: [Atlassian описывает автоконвертацию](https://confluence.atlassian.com/display/DOCM/Jira+Issues+Macro) для прямой вставки URL в редактор. Для точного макроса используйте HTML уже созданного в Confluence макроса и проверьте результат вставки в своей версии редактора.

Поля «Название сервиса» и «Команда» тоже принимают HTML-фрагмент. Вставьте код в поле и отметьте «HTML» либо нажмите «Редактор…», вставьте код или возьмите HTML скопированного фрагмента Confluence из буфера. Редактор автоматически включает режим HTML. Фрагмент вставляется целиком в соответствующую ячейку карточки; при выключенном «HTML» содержимое поля остаётся обычным текстом. Флаги HTML и «Приоритет» сохраняются отдельно для каждого сервиса. Макросы и их `data-macro-*` атрибуты сохраняются как HTML; итог работы редактора Confluence зависит от того, как он обрабатывает вставку.

Кнопка «Скопировать все строки» копирует описания с текущими правками и разделителем `;`. Для переноса вставьте текст через «Вставить из Excel…» на другой машине и нажмите «Сохранить». Текст также можно сохранить в CSV.

Скопируйте полную исходную страницу Confluence и нажмите «Сохранить буфер как шаблон», чтобы использовать её позднее. Кнопка «Заполнить шаблон из буфера» работает непосредственно с текущей полной страницей в буфере. Кнопка «Заполнить сохранённый шаблон» берёт страницу из настроек и заполняет её даже при пустом буфере. Кнопка «Сохранённый шаблон + буфер» берёт сохранённую страницу, переносит из текущего буфера найденные значения карточки, комментарии микросервисов, новые строки и ключи объектов доступа вместе с комментариями, настройки параметров и дополнительную информацию, затем применяет данные YAML и J2. В этом режиме текущий буфер может содержать только часть страницы. Результат каждой команды копируется в буфер для вставки в Confluence.

В таблицах микросервисов и настраиваемых параметров достаточно строки заголовка: если строки-образца нет, приложение создаёт строки по структуре заголовка. Это позволяет повторно использовать страницу, в которой после предыдущей генерации эти таблицы опустели.

Карточка распознаётся и внутри таблиц макросов Confluence. Из старой страницы переносятся все совпавшие поля шапки, включая описание, поля Vault, адрес доменного API, схемы, согласования, HealthCheck и микрофронты. Поля сопоставляются по основному названию без поясняющих подсказок, завершающих двоеточий и пустых служебных колонок. Вложенные таблицы и макросы в значениях сохраняются целиком. После переноса применяются значения из UI и YAML. Макросы карточки не используются как источник блока «Дополнительная информация».

Поле «Vault. Переменная с ключами для предоставления доступа» заполняется именем единственной переменной из значения `GrpcSettings__ServerSettings__AllowedServices` в выбранном secrets J2. Например, `"{{GRPC_SETTINGS_SERVER_SETTINGS_ALLOWED_SERVICES}}"` даёт `GRPC_SETTINGS_SERVER_SETTINGS_ALLOWED_SERVICES`. Найденная переменная заменяет значение старой страницы; если подходящей записи в secrets нет, значение сохраняется из шаблона.

В «Объектах доступа» остаются только строки, содержащие имена переменных из выбранных `*.deploy.j2` или `*.secrets.j2`. В колонках адреса и Vault из исходного шаблона удаляются имена, которых нет в этих файлах; новые имена по совпадению префикса не добавляются. Несколько имён в одной ячейке проверяются по отдельности, в том числе если они стоят в одном абзаце.

После заполнения паспорта кнопка «Проверить переменную…» показывает для введённого имени, какие файлы J2 были прочитаны, в какой строке объектов доступа ключ находился до и после заполнения и попал ли он в итоговую таблицу параметров или микросервисов. Отчёт относится к последней успешной генерации с J2.

В таблице настраиваемых параметров колонка «Значение по умолчанию» для ключей из общих YAML содержит пометку «Дефолтное значение в базовых параметрах». Для остальных ключей, найденных в YAML сервиса, выводится итоговое значение после объединения слоёв, включая `*-prod`. Значение заменяет текст из шаблона и вставляется как обычный текст. Если ключа в YAML нет, содержимое ячейки сохраняется из шаблона.

Папка сервиса в `app-params` необязательна. Если её нет, используются значения из корневого `application.yml` или `application.yaml`. Для ресурсов дополнительно загружаются `cpu_req`, `mem_req`, `cpu_lim`, `mem_lim` и `DEFAULT_RESOURCES_*` из корневого `application-prod.yml` или `application-prod.yaml`, даже если папки сервиса нет. Остальные параметры из `application-prod` в этом случае не загружаются. Ссылка в карточке ведёт на корень `app-params`. Если `deploy_num`/`replicas` отсутствуют или пусты, количество Pod равно `1`. Отсутствующие `namespace`/`namespace_name` сохраняют значение из скопированного шаблона.

Пустые YAML-файлы допускаются: они не добавляют значений, поэтому берутся параметры из других YAML-слоёв. Если ресурс не указан и подходящий дефолт отсутствует, в карточке выводится «значение не найдено».

Requests и Limits вычисляются отдельно для CPU и памяти: `cpu_req`, `mem_req`, `cpu_lim`, `mem_lim` имеют приоритет над `DEFAULT_RESOURCES_{UI|API|DAEMON}_{REQUEST|LIMIT}`. Дефолты читаются как YAML-объекты с ключами `cpu` и `memory` из объединённых слоёв с обычным порядком перекрытия. Значения, взятые из этих объектов, получают пометку «(значение по умолчанию)». Фиксированных резервов ресурсов нет; отсутствие каждого значения отмечается отдельно.

Тип определяется по нормализованному имени деплоя: сначала проверяются правила webapi (включая api, bff, grpc и другие согласованные имена), затем daemon (worker, scheduler, integration и другие). Если ни одно правило не совпало и в папке сервиса и её подпапках нет `appsettings*.j2`, используется UI. Имена файлов проверяются без учёта регистра; служебные каталоги `.git`, `node_modules`, `bin`, `obj` и символические ссылки не просматриваются. Если тип не определён, используются только явно заданные ресурсы.

Для UI основной J2 необязателен. При выборе «Без J2 (для UI)» таблицы микросервисов, объектов доступа и параметров сохраняются из шаблона; имя деплоя и ссылка на репозиторий строятся по выбранной папке. В поле «Шаблон конфига» выводится «Не используется». Для прочих типов основной J2 требуется.

Для памяти в Requests и Limits числовые значения `mem_req` и `mem_lim` дополняются единицей `Mi`; значения с уже указанной единицей, например `800Mi` или `1Gi`, выводятся без изменений.

Индикатор в окне автоматически проверяет HTML в буфере обмена. Он узнаёт шаблон по характерным полям даже в скопированной отдельно карточке сервиса. Это предварительная проверка: прямое заполнение требует полной исходной страницы, а режим с сохранённым шаблоном принимает фрагмент. После генерации индикатор сообщает, что в буфере уже готовый паспорт.

Пути, выбранный сервис, название, команда и шаблон по умолчанию сохраняются в `%LOCALAPPDATA%\ServiceAutoPassport\settings.json`. При первом запуске приложение также прочитает прежний `settings.json` из текущей папки или рядом с исполняемым файлом, если он есть. Для паспорта рядом с `appsettings.deploy.j2` или `appsettings.j2` ищется `appsettings.secrets.j2`; также поддерживается `secrets.j2`. Для числа Pod принимаются `deploy_num` или `replicas`, для пространства имён — `namespace` или `namespace_name`. Если `autoscale` отсутствует или пуст в YAML, в карточке указывается «нет». Файлы `.yaml` также поддерживаются.

AIO-сборка публикуется отдельным профилем (нужен .NET SDK на машине сборки):

```powershell
dotnet publish src/ServiceAutoPassport/ServiceAutoPassport.csproj -c Release -p:PublishProfile=WinX64-AIO
```

Результат: `artifacts/win-x64-aio/ServiceAutoPassport.exe`. Профиль включает управляемые и нативные компоненты runtime в один сжатый EXE. При запуске нативные библиотеки распаковываются в служебный каталог .NET; установка runtime не требуется. Trimming отключён для совместимости с WinForms и привязкой данных. Профиль можно выбрать также в окне Publish в Visual Studio. [Описание single-file публикации Microsoft](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview).

Готовый Windows файл находится в `artifacts/win-x64/ServiceAutoPassport.exe`; для него нужен установленный .NET 8 Desktop Runtime. Чтобы пересобрать его:

```powershell
dotnet publish src/ServiceAutoPassport/ServiceAutoPassport.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o artifacts/win-x64
```

При ошибке генерации исходный буфер не меняется. Для прямого заполнения следующего сервиса вновь скопируйте исходную страницу шаблона. Режим с сохранённым шаблоном восстанавливает его исходные строки перед заполнением.

## Проверка

```powershell
dotnet test ServiceAutoPassport.sln -c Release
```

Тесты проверяют слои YAML, обработку встроенного сокращённого шаблона Confluence, сохранение макросов и формирование `HTML Format`. Локальные экспорты буфера для ручной проверки хранятся в `artifacts/one_block` и `artifacts/whole_page` и не входят в Git. Фактическую вставку в Confluence нужно проверить в Windows с доступом к редактору.

## Общая сетевая карта

Откройте вкладку «Сетевые подключения». Список сервисов, окружения, порты, анализ, результаты и сетевой шаблон находятся на этой вкладке. Поля паспорта, его шаблон и генерация находятся на вкладке «Паспорт сервиса». У вкладок отдельные индикаторы буфера и независимо сохраняемые пути app-params; при первом запуске новой версии сетевой путь заполняется прежним общим значением.

### Быстрый старт без шаблона и буфера

На сетевой вкладке укажите app-params, добавьте main J2 сервисов и нажмите **«Анализ: базовая таблица»**. Приложение использует встроенный Table Transformer с таблицей подключений по окружениям.

После проверки подключений нажмите «Копировать таблицу» и вставьте макрос в нужное место в редакторе Confluence. Для схемы нажмите «Копировать draw.io XML» и вставьте XML в **Extras → Edit Diagram** своего макроса draw.io.

Флажок «Включить» у подключения управляет и схемой, и таблицей: снятый флажок убирает соответствующую стрелку и запись из обоих результатов при следующем копировании. Общий блок и строка таблицы остаются, пока есть включённые подключения к ним; исключённые сервисы-вызовы в их подписях не показываются. Если снять все флажки, в схеме останутся выбранные сервисы без стрелок, а в таблице — только заголовки. Выбор сохраняется в настройках.

### Свой сетевой шаблон (необязательно)

Скопируйте из редактора Confluence макрос **Table Transformer** с одной исходной таблицей. Можно скопировать и целую страницу с одним таким макросом. Кнопка «Сохранить шаблон таблицы из буфера» записывает макрос с его настройками. Из старого шаблона целой страницы приложение извлекает макрос при анализе.

1. Укажите корень app-params и добавьте main J2 всех сервисов. Можно выбирать несколько файлов из разных каталогов. Парные `*.secrets.j2` либо `secrets.j2` подключаются автоматически. Исправьте YAML-папки и подписи сервисов при необходимости.
2. При необходимости укажите собственные адресные переменные каждого сервиса через запятую. При анализе для `SVC_` программа также ищет целевой сервис по prod-хосту. Имя хоста должно начинаться с полного нормализованного имени J2-папки или YAML-папки. После имени допустим суффикс с неалфавитной границей, например `accounts-web-blue` для `accounts-web`. При неоднозначности выберите «Целевой сервис» вручную. Ручной выбор имеет приоритет, затем учитываются собственные адресные переменные.
3. Задайте окружения в нужном порядке (начальные — dev, test, demo, lt, preprod, prod) и стандартные порты. Для своего шаблона нажмите «Анализ: таблица из буфера» или «Анализ: сохранённая таблица».
4. Просмотрите найденные подключения и исключите ссылки на документацию. Можно изменить протокол и целевой сервис. Названия и блоки внешних узлов редактируются в окне «Параметры сети…». Для `Unknown` с пустым портом укажите протокол. Предпросмотр показывает адреса по окружениям и отмечает отсутствующие значения и циклические ссылки.
5. Нажмите «Копировать таблицу» и вставьте макрос в Confluence. Выбранное окружение `prod` идёт сразу после «Элемент», остальные — в порядке из настроек. Для обновления схемы отдельно скопируйте draw.io XML, вставьте его в **Extras → Edit Diagram**, нажмите **Apply** и сохраните диаграмму.

При создании новой страницы сначала создайте её собственный draw.io макрос. Простое копирование макроса между страницами не копирует его вложение. Программа не загружает вложения и не меняет Confluence через API.

Карта показывает исходящие подключения из main/secrets J2, когда в хосте или пути URL есть J2-переменная, имя которой заканчивается на `URL` или `HOST` без учёта регистра: URL/URI/Host/Endpoint, пары Host/Port, списки брокеров, строки подключения к БД. Подключение с переменной только в порту или query string пропускается. Если подходящая переменная есть только в пути URL, подключение добавляется с фиксированным хостом. Kestrel/listener settings, VirtualHost, относительные URL, пароли, сертификаты и прочие несетевые параметры исключаются. Поддерживаются JSON и YAML конфигурации с простыми `{{ VARIABLE }}`; управляющие конструкции Jinja и выражения-фильтры сообщаются как неподдерживаемые. Ошибки разбора блокируют анализ; новые результаты не копируются при ошибке.

Для каждого сервиса и окружения порядок слоёв: `application` → базовый YAML сервиса → `application-{env}` → YAML сервиса `{env}`. Корневой файл окружения читается даже без YAML-папки сервиса. Ссылки переменных раскрываются рекурсивно. Secrets заменяет соответствующие пути основной конфигурации; `__` преобразуется в разделитель вложенных ключей.

Окно «Параметры сети…» показывает все сохранённые внешние зависимости. На общий адресный параметр приходится одна строка с названием элемента, блоком и блоком-родителем. Новые параметры добавляются при анализе. Вставка из Excel принимает колонки «Найденный параметр», «Название элемента», «Блок» и необязательную четвёртую колонку «Блок-родитель». Пустая четвёртая ячейка очищает родителя. При вставке трёх колонок родитель сохраняется, если имя блока осталось прежним. Правки применяются к схеме и таблице после нажатия «Сохранить», повторный анализ не нужен. Названия и блоки выбранных сервисов задаются в верхней таблице. После первой колонки Table Transformer идут все настроенные окружения. Разные адреса или порты одного узла перечисляются в ячейке с именами вызывающих сервисов. Технические колонки доступны при редактировании исходной таблицы внутри макроса.

Для внешнего узла в отдельном блоке первая колонка показывает имя блока. Например, у блока `Kafka` с элементом «Топики Kafka» строка будет называться `Kafka`, а узел на схеме — «Топики Kafka». Для общих блоков, стандартного `k8s` и узлов без контейнера в таблицу выводится название элемента. Состав блока учитывает найденные узлы до фильтрации по галочкам. Техническая колонка «Подпись узла» сохраняет текст схемы для предзаполнения.

Кнопка «Предзаполнить из шаблона» берёт названия и блоки из первой заполненной сетевой таблицы. Она проверяет текущий шаблон, сохранённый шаблон, макрос, скопированный при анализе, и текущий буфер обмена. Если таблицы с данными нет, скопируйте заполненный Table Transformer из редактора Confluence и нажмите кнопку снова. Однозначно найденные параметры добавляются в общий справочник. Ранее заданные названия и блоки сохраняются, предзаполнение заменяет только новые автоматические значения. Изменения вступают в силу после нажатия «Сохранить». У новых автоматических названий обрезаются конечные `URL` и `HOST`, а исходные ключи J2 остаются целыми.

Кнопка «Скопировать все строки» в «Параметрах сети…» копирует справочник с заголовками и разделителем `;`. При импорте также поддерживается табуляция. Вставьте таблицу через «Вставить из Excel…» на другой машине, выберите действие для совпадений и нажмите «Сохранить». Импортированная строка с фиксированным хостом ждёт однозначного совпадения с подключением при анализе.

Чтобы загрузить настройки заново, выделите строки и нажмите «Удалить выбранные». Затем в том же окне выполните предзаполнение из шаблона или вставку из Excel и нажмите «Сохранить». Если сохранить удаление без повторного импорта, подключение остаётся на карте с автоматическим названием и блоком по умолчанию. Следующий анализ снова обнаружит его параметр.

Явный порт имеет приоритет. Стандартный порт берётся из редактируемого списка и помечается «порт по умолчанию». Для неоднозначных строк подключения выберите протокол в окне проверки. В результат выводятся хосты и порты без учётных данных, путей URL и query string.

В верхней таблице поле «Колонка схемы» задаёт положение сервиса. Центр — `0`, отрицательные номера находятся слева, положительные — справа. Пустое поле означает `0`. Например, между сервисами в колонках `0` и `2` остаётся место для колонки `1`. Внешние зависимости с адресным параметром `SVC_` занимают `-1`, остальные — `1`. После правки колонки сразу нажмите «Копировать draw.io XML».

Каждое имя блока создаёт один контейнер на всю карту. По умолчанию узлы входят в `k8s`, а их поле «Блок-родитель» пустое. Чтобы поместить `Kafka` внутрь `k8s`, укажите `Kafka` в колонке «Блок», а `k8s` в колонке «Блок-родитель». Родитель применяется ко всем узлам блока. Если заполнен только «Блок-родитель», узел помещается прямо в него. Две пустые ячейки оставляют узел отдельным. Схема поддерживает два уровня контейнеров.

Блоки и отдельные узлы укладываются по высоте в каждой колонке независимо. Общий контейнер занимает место во всех колонках между его краями. Внутри контейнера интеграции располагаются ниже сервисов того же блока. Каждый вызывающий сервис соединяется с общей зависимостью своей стрелкой. Если после применения флажков «Включить» в блоке видна одна внешняя интеграция и блок не содержит дочерних контейнеров, стрелки заканчиваются на его рамке. Дуги на пересечениях имеют размер 8 pt.

Подпись стрелки показывает порт и известный протокол в скобках, например `443 (HTTPS)`. Разные порты перечисляются в одной подписи. Протокол можно скрыть, а ключи appsettings добавить флажками над таблицей проверки. Флажок «Цвет стрелок по сервисам» задаёт один цвет на все исходящие стрелки каждого сервиса и включён по умолчанию. Если его снять, все стрелки будут серыми. Настройки карты и выбор подключений сохраняются в локальном settings.json. Изменения списка сервисов и окружений требуют нового анализа.

### Топики Kafka из prod-конфига

На вкладке «Сетевые подключения» укажите каталог app-params, добавьте сервисы и нажмите **«Топики Kafka»**. Приложение читает J2 всех добавленных сервисов, включая парные secrets, и подставляет значения из YAML-слоёв prod по тем же правилам, что и сетевая схема. Для каждого кластера в каждом сервисе в буфер копируется таблица с колонками «Топик», «Чтение», «Запись». Заголовок показывает имя сервиса и путь раздела, например `Daemon — KafkaSetting.Cdc`. Один топик может иметь обе отметки. Статус показывает число таблиц и строк с топиками.

Под заголовком кластера отображаются имя переменной из `BootstrapServers` и её prod-адреса, например `KAFKA_CDC_HOST → broker1:9092, broker2:9092`. Для каждого брокера выводится хост с указанным портом. Если prod-адрес отсутствует, отчёт показывает «Адрес prod не найден» перед таблицей топиков.

Встроенные правила ищут чтение в `Consumer.Topics[]` и запись в `Producers[].TopicId`. Чтобы учесть другую структуру, откройте **«Правила топиков…»** и задайте направление и путь от корня JSON. `*` соответствует одному произвольному ключу, `{kafka}` отмечает раздел кластера, `[]` перебирает элементы массива. Например, правило `*.{kafka}.Producers[].TopicId` найдёт запись в `KafkaSetting.Cdc.Producers`. Правила сохраняются в локальном `settings.json`.

### Проверка вставки в Confluence

Вставьте скопированный Table Transformer в тестовую страницу Confluence. Проверьте, что макрос открывается для редактирования, а после сохранения показывает «Элемент» и настроенные окружения. Вставьте XML в редактор draw.io и проверьте, что две стрелки к общей БД идут от своих сервисов напрямую. При перемещении `k8s` вложенные узлы должны перемещаться вместе с контейнером.
